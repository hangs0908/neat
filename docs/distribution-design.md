# 배포·업데이트 설계 인터뷰

상태: 개별 정책 합의 완료. 전체 설계 확인 후 구현을 시작한다. 공개 배포는 별도 확인 후 진행한다.

## 확정한 요구사항

- 사용자에게 무료로 제공하고, 개발자의 추가 배포 비용도 0원으로 한다.
- Homebrew를 통해 배포하고 소스를 공개하고자 한다.
- 업데이트는 자동으로 확인해 알리되, 설치는 사용자가 선택한다. 수동 확인 버튼도 제공한다.
- 공증 없는 배포에서 발생할 수 있는 최초 실행 허용 절차를 수용한다.
- 비공개 PlatformRuntimeKit은 유지하고 Neat 앱 소스를 공개하는 방식으로 시작한다. 모든 구성요소가 오픈소스라고 안내하지 않는다.
- 최초 설치는 자체 Homebrew tap으로 제공한다.
- 앱은 새 버전을 알리고, 사용자가 명시적으로 설치를 선택하면 다운로드·서명 검증·앱 교체·재실행을 처리한다. 알림 표시만으로 설치하거나 재실행하지 않는다.
- 메뉴에 수동 업데이트 확인 기능을 제공하고 기존 Sparkle 코드를 활용한다. 업데이트 파일은 EdDSA로 서명한다.
- 첫 배포는 macOS 27 이상·Apple Silicon으로 제한한다. 이전 macOS와 Intel 지원은 첫 배포에 포함하지 않는다.
- 초기 실행 과정에서 자동 확인 동의를 받아 활성화한다. 설정에 자동 업데이트 확인 스위치를 제공하며, 꺼도 수동 확인은 가능하다.
- Neat 최초 공개 버전은 0.1.0으로 하고 단일 공개 채널을 운영한다. 원본 Thaw 버전과 베타·알파 채널을 사용하지 않는다.
- 버전 태그를 기준으로 빌드·검증·릴리스 초안 생성을 자동화한다. 개발자가 직접 확인해 공개한 버전만 업데이트 대상으로 알린다.

## 구현 범위

- Neat 전용 버전 정보·업데이트 피드·공개 서명 키를 설정하고 비활성화된 업데이트 기능을 연결한다.
- 기존 Sparkle 기능을 활용해 자동 확인 동의, 설정 스위치, 수동 확인 메뉴, 사용자 선택에 따른 설치 흐름을 제공한다.
- GitHub Releases에 배포 파일을 제공하고 자체 tap에 버전·다운로드 URL·체크섬·지원 범위를 정의한다. 공개 전 업데이트 피드를 노출하지 않도록 게시 순서를 정한다.
- 공개 저장소의 표준 GitHub Actions 실행 환경과 무료 호스팅을 사용한다. 유료 실행 환경·유료 서비스는 추가하지 않고 저장소의 무료 저장 공간 한도를 지킨다.
- 기존 로컬 개발용 빌드 흐름과 배포용 빌드를 구분한다. 개인 키나 서명용 인증서 비밀 정보는 저장소·배포 파일에 포함하지 않는다.
- README에 설치·최초 실행 허용·업데이트 방법, 비공개 구성요소 및 라이선스 고지를 반영한다. 구성요소의 재배포 조건을 확인한다.

## 완료 조건

- 자동 테스트와 개발 대화 기록을 공유하지 않은 별도 에이전트의 독립 코드 리뷰를 통과한다.
- macOS 27·Apple Silicon에서 실제 배포 파일을 Homebrew로 설치하고 최초 실행 허용 및 앱 권한 부여 후 실행한다.
- 구버전에서 새 버전 알림을 확인하고, 설치 선택 전에는 앱 교체·재실행이 발생하지 않는지 확인한다.
- 사용자 설치 선택 후 다운로드·서명 검증·교체·재실행이 성공하고, 기존 설정과 앱 동작에 필요한 권한이 유지되는지 확인한다. 권한 유지 실패는 검증 실패로 처리하고 해결 또는 설계 재협의 전에는 완료로 보고하지 않는다.
- 자동 확인 동의·거부와 설정 스위치, 수동 확인, 최신 버전 상태, 네트워크 실패, 검증 실패 시 기존 앱 보존을 확인한다.
- 릴리스 초안이 업데이트로 노출되지 않고 공개 후에만 노출되는지 확인한다. 동일 배포 파일을 앱 업데이트와 Homebrew에서 사용할 때 버전이 역행하지 않는지 확인한다.
- 실제 조작 근거를 남기고 테스트로 변경한 사용자 상태를 복원한다. 원격 CI·PR 승인·공개 배포와 로컬 검증 결과는 구분해 보고한다.

확정한 비용·공개 범위의 배경은 [ADR-0001](adr/0001-zero-cost-distribution.md)에 기록한다.

## 조사 근거

- [Apple 실행 정책](https://support.apple.com/en-us/102445): 공증·개발자 확인이 없는 앱은 차단 및 개별 허용 절차가 발생할 수 있다.
- [Homebrew 공식 cask 수록 조건](https://docs.brew.sh/Acceptable-Casks): Gatekeeper 검사 통과가 필요하다.
- [자체 tap](https://docs.brew.sh/How-to-Create-and-Maintain-a-Tap): 공식 저장소와 별도로 운영할 수 있다.
- [Sparkle 배포 보안](https://sparkle-project.org/documentation/): HTTPS와 EdDSA 업데이트 서명을 사용하고, 가능하면 Developer ID 서명·공증을 권장한다. EdDSA 서명은 Apple 공증을 대체하지 않는다.
- 원본의 [라이선스 설명](../upstream/README.md#license)은 PlatformRuntimeKit을 비공개 구성요소로 명시한다. 배포 조건은 [추가 허용 조항](../upstream/LICENSE-EXCEPTION)과 해당 구성요소 라이선스를 함께 확인해야 한다.

실제 배포본 설치·업데이트·권한 유지 검증은 수행하지 않았다.
