# 배포·업데이트 검증 기록

최신 수정 커밋 `4b94a0c`에서 이전 테스트 실패와 업그레이드 후 원본 새 소식 자동 표시를 해결했다. 전체 네이티브 테스트는 1,735개 성공·실패 0·권한 조건부 건너뜀 1개다. 아래 이전 기록은 당시 결과이며 마지막 수정 검증 절이 최신 상태다. 공개 배포·라이선스·원격 CI 판정은 각각 구분한다.

2026-10-21, macOS 27.0.1(26A434), Apple Silicon, Xcode 27.1에서 수행했다. 구현 커밋은 `e6eed05`이며 아래 기록은 공개 배포 완료 판정이 아니다.

## 독립 코드 리뷰

별도 에이전트에 개발 대화 기록 없이 요구사항과 `446bcfe..3a2a04c` diff를 전달했다. 리뷰 중 코드를 수정하지 않았다. 별도 설정 프로세스에서 동의해도 본체 updater가 시작되지 않는 문제 1건을 보고했다.

`remoteConsentStartsUpdater`와 `forwardingProcessDoesNotStartUpdater`가 수정 전 실패하는 것을 확인했고, `e6eed05`에서 본체가 동의 변경에 따라 시작하고 별도 설정 프로세스는 대신 시작하지 않도록 수정했다. 수정 후 위 37회 테스트가 통과했다. 그 밖의 검토 범위에서 리뷰 에이전트가 확정한 추가 버그·회귀·보안 문제는 없었다. 수정 뒤 추가 독립 재리뷰를 수행했다고 주장하지 않는다.

## 실제 조작

Homebrew는 임시 tap `neat-tests/rehearsal`과 `build/InstalledApps`를 사용했다. 최종 배포 스크립트로 만든 실제 Release ZIP에서 cask를 생성하고 로컬 파일 URL로 설치했다. 설치·앱 복사·체크섬·macOS 27 및 arm64 조건 확인과 제거가 성공했다. 임시 tap과 설치 앱을 제거하고 개발자 모드 변경을 복원했다. 공개 GitHub 다운로드·격리 속성에 따른 Gatekeeper 최초 실행은 이 검사로 대체하지 않는다.

GUI는 실제 최신 Debug 모듈의 `SettingsWindow`, 동의 시트, `SimpleModeSettingsPane`, `UpdatesManager`와 Sparkle을 별도 진입점으로 실행했다. 테스트 식별자는 `local.hangjin.Neat.UpdateTest`다. 전체 메뉴 막대 초기화와 로그인 항목 등록을 실행하지 않아 기존 사용자 메뉴 배치·설정·앱·권한을 건드리지 않았다. 서버는 127.0.0.1에만 바인딩했다. 운영 피드와 운영 앱 식별자는 변경하지 않았다.

## 남은 검증과 배포 조건

- 사용자가 추가 검증과 테스트 권한 부여를 승인했다. 아래 추가 검증 결과를 따른다. 기존 Neat 권한은 초기화하지 않았다.
- 공개 릴리스 전 초안 비노출, 공개 후 GitHub 피드 다운로드, 공개 이벤트의 tap PR 생성, 실제 공개 파일의 최초 설치를 확인해야 한다. 이번 작업에서는 태그·공개 릴리스·main 병합을 실행하지 않는다.
- Actions secrets 3개는 해당 저장소에 등록했다. 키·인증서는 저장소 밖 `~/Library/Application Support/NeatRelease/`에 보관한다.
- 저장소의 Actions PR 생성·승인 허용 설정은 현재 꺼져 있다. tap PR 자동 생성에는 설정 변경이 필요하며, 임의로 봇 승인 권한을 확장하지 않았다.
- 고정 PlatformRuntimeKit 수정본 배포에 필요한 서면 허가는 확인되지 않았다. [배포 운영 문서](distribution.md)를 따른다.
- 전체 네이티브 테스트 실행 결과와 로컬 수정행 커버리지는 아래에 기록했다. 원격 Sonar 판정은 실행하지 않았다.


## 2026-10-21 추가 검증

### 실제 Release 앱과 권한 유지

별도 진입점 대신 실제 Release 실행 파일을 사용했다. 테스트 식별자는 `local.hangjin.Neat.DistributionTest`다. 테스트 앱의 식별자·표시명·로컬 피드·URL 등록만 분리하고 이전/새 버전을 같은 고정 배포 인증서로 서명했다. 운영 앱과 운영 피드는 변경하지 않았다. 서버는 127.0.0.1에 바인딩했다.

- 실제 권한 화면의 버튼으로 손쉬운 사용을 요청하고, 사용자의 Touch ID 인증 후 테스트 앱만 허용했다. 화면 기록과 단일 메뉴 막대 배치 파일 접근도 허용했다.
- 권한 화면에서 ‘Neat 시작’을 눌러 일반 초기화·동의·설정 화면까지 진행했다. ‘수동으로 확인’을 선택하고 테스트 앱의 로그인 실행 등록은 껐다.
- 실제 0.1.0 build 116에서 ‘업데이트 확인…’ → ‘업데이트 설치’ → ‘설치 & 재실행’을 직접 클릭했다. 새 버전은 `RELEASE_VERSION=0.1.1 BUILD_NUMBER=117`로 별도 컴파일했다. 메타데이터만 바꾼 동일 실행 파일의 선행 리허설로 결과를 대체하지 않았다.
- 새 프로세스의 설정 화면에 버전 0.1.1, 손쉬운 사용·화면 기록·배치 파일 접근 모두 Granted, 자동 확인·로그인 실행 모두 꺼짐을 확인했다. 다시 확인을 눌러 ‘0.1.1이 현재 최신 버전’ 안내도 확인했다. 화면과 접근성 트리를 캡처했다.
- 초기 Debug 리허설에서는 자동 확인을 켜고 마지막 검사일을 2000-01-01로 설정한 뒤 재실행했다. 수동 확인 없이 업데이트 안내가 나타났고 서버에는 앱캐스트 요청만 기록됐다. 실제 24시간을 기다린 검사는 아니다.
- 격리 속성을 붙인 복제 앱을 실제 실행해 Gatekeeper 차단 안내를 확인했다. 시스템 설정의 해당 앱 ‘그래도 열기’와 후속 확인을 거쳐 앱이 App Translocation 경로에서 실행됐고, Finder로 재열어 0.1.1 설정 화면을 확인했다. 전역 Gatekeeper 정책은 변경하지 않았다. 공개 서버에서 내려받은 파일 검사를 대신하지 않는다.

발견한 실제 표시 문제: 0.1.1 설치 후 `AppState.presentWhatsNewForUpgradeIfNeeded()`가 원본 Thaw의 3.0.0-alpha.9 내용이 담긴 ‘What’s New’를 자동으로 열었다. Neat 릴리스 내용으로 연결하거나 이 자동 표시를 제거하는 조치가 배포 전에 필요하다. 이번 검증 작업에서 해당 동작을 수정했다고 보고하지 않는다.

테스트 후 사용자 인증을 받아 테스트 앱의 화면 기록·손쉬운 사용 스위치가 모두 off, 기존 Neat 스위치는 on인 것을 확인했다. 테스트 앱을 종료하고 전용 defaults 도메인을 제거해 배치 파일 접근 북마크도 남기지 않았다. 127.0.0.1 서버를 종료하고 기존 `/Applications/Neat.app`을 다시 실행했다. 사용자 프로필 디렉터리는 검사 전후 모두 비어 있었다. 원래 0.1.0 배포 파일도 `build/release`에 복원했고 ZIP 체크섬은 이전 값과 같다.

### 독립 재리뷰와 남은 외부 검증

별도 리뷰 에이전트가 개발 대화 없이 `446bcfe..a9d5806`과 동의 전달 수정 `e6eed05`를 다시 검토했고 조치할 정확성·회귀·보안 문제를 발견하지 못했다. 메타데이터 3건도 독립 통과했다. 추가 메뉴 테스트 리뷰에서는 자동 확인 OFF를 설정하지 않고 OFF라고 주장하는 문제를 지적했다. 테스트명을 실제 검증 범위인 ‘메뉴 명령 전달’로 좁혔고 재실행했다. 제품 코드는 바꾸지 않았다.
