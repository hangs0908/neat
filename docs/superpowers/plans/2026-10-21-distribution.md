# 무료 배포와 업데이트 구현 계획

> 실행: `superpowers:executing-plans`로 이 세션에서 직접 구현하고 마지막에 독립 코드 리뷰를 수행한다.

목표: 자체 Homebrew tap과 GitHub Releases로 배포하고, 동의한 자동 확인 및 사용자가 선택하는 설치를 제공한다.
구조: 기존 UpdatesManager와 Sparkle UI를 사용한다. 빌드·서명·메타데이터 생성은 배포 스크립트로 분리한다.
기술: SwiftUI, Sparkle 2.10.0, GitHub Actions, Homebrew Cask.
명세: [배포 설계](../../distribution-design.md).

## 제약

- 0.1.0, macOS 27 이상, arm64, 단일 공개 채널, 추가 배포 비용 0원.
- 자동 다운로드·자동 설치를 제공하지 않는다. 동의 전에는 자동 확인도 하지 않는다.
- 개인 키를 저장소에 넣지 않는다. 초안은 업데이트 대상에서 제외한다.
- 라이브러리의 수정본 배포에 서면 허가가 필요하다는 조건을 고지한다. 무료라는 사실을 허가로 간주하지 않는다.
- 기존 사용자 설정·키체인·실행 앱을 검증을 위해 초기화하지 않는다. 별도 앱 식별자와 테스트 데이터로 검증한다.

## 리뷰 중점

- 과거 자동 다운로드 설정이 남아 있어도 자동 다운로드·설치를 하지 않는가.
- 동의 거부 후 수동 확인과 재실행이 자동 확인을 켜지 않는가.
- 서명 실패·변조 업데이트·네트워크 실패가 기존 앱을 보존하는가.
- 초안·다른 채널·이전 버전이 사용자에게 노출되지 않는가.
- 자체 서명한 새 앱의 권한을 유지할 수 있는가. 실제 확인 전에는 보장하지 않는다.

## 작업 1: 업데이트와 UI

파일: `upstream/Thaw/System/{Updates,AutomaticUpdates}.swift`, 동의 시트·설정창·간단 설정·메뉴·AppState·Constants·Info.plist·project.pbxproj 및 기존 업데이트 테스트.

- [ ] AutomaticUpdatesTests에 자동 다운로드 선택이 없는 정책과 잔존 설정의 확인 전용 매핑 테스트를 추가해 실패를 확인한다.
- [ ] 공개 채널만 허용하고 모든 자동 다운로드 경로를 차단한다. Sparkle 기본 사용자 설치 UI를 재사용한다.
- [ ] 동의 시트와 설정 스위치·수동 확인 메뉴를 연결한다. 동의 없이 주기적 확인을 시작하지 않는다.
- [ ] 0.1.0과 Neat 전용 업데이트 피드·키를 설정한다.
- [ ] 정책·네이티브 테스트, SwiftLint와 수정 파일 SwiftFormat을 실행한다.
- [ ] 의미 있는 단위로 한국어 커밋한다.

## 작업 2: 릴리스와 tap

파일: `scripts/build-release.sh`, `scripts/release-metadata.py`, `scripts/test-release-metadata.py`, `.github/workflows/release.yml`, `.github/workflows/publish-release.yml`, `docs/distribution.md`, README·CHANGELOG.

- [ ] 메타데이터 생성기의 버전·서명·체크섬·지원 범위·오류 입력 테스트를 먼저 작성해 실패를 확인한다.
- [ ] 고정 서명 인증서를 임시 키체인으로 읽어 빌드·서명하고 ZIP·앱캐스트·cask를 만든다. 실패 시 게시하지 않는다.
- [ ] 태그에서 검증된 릴리스 초안을 생성하고, 공개 이벤트에서만 앱캐스트와 tap 갱신을 게시한다.
- [ ] 무료 표준 runner를 사용하고 배포 조건·비밀 관리·공개 순서를 문서화한다.
- [ ] 테스트·셸 문법·워크플로 정적 검사를 통과하고 커밋한다.

## 작업 3: 독립 리뷰와 실제 검증

- [ ] 별도 에이전트에 요구사항과 diff만 전달해 정확성·회귀·보안 리뷰를 요청한다. 리뷰 중 수정하지 않는다.
- [ ] 필요한 수정에 실패 재현 테스트를 추가하고 해결한다.
- [ ] 별도 식별자의 최신 앱에서 동의·거부·스위치·수동 확인과 로컬 서명 업데이트를 실제로 조작한다.
- [ ] 테스트 상태를 복원하고 결과·미검증 항목·배포 제약을 기록한다.
- [ ] 브랜치 PR과 CI 결과를 준비한다. 병합·공개 배포는 확인받기 전 수행하지 않는다.
