# 프로필 파일 처리 테스트 보강 계획

목표: 제품 코드를 수정하지 않고 프로필 이름 변경·복제·저장 내용 교체의 데이터 보존을 검증한다.

구조: `ProfileManager(profilesDirectory:)`에 테스트별 임시 폴더를 전달하고, 작업 뒤 새 관리자로 파일과 목록을 다시 읽는다. Swift Testing을 사용한다.

요구사항: 사용자와 합의한 커버리지 개선의 첫 단계. 실제 사용자 프로필·설정·메뉴 막대를 변경하지 않는다. 커버리지 제외 항목을 늘리지 않는다.

## 작업 및 검증

- [x] `ProfilePersistenceTests.swift`에 이름 변경과 복제의 식별자·전체 설정·연결 정보 보존을 검증한다.
- [x] 저장 내용 교체와 인코딩 실패 시 기존 파일 보존을 검증한다.
- [x] 원본 파일 누락·손상 시 이름 변경과 복제가 실패하고 목록을 보존하는지 검증한다.
- [x] 임시 폴더 삭제 실패도 테스트 실패로 기록한다.
- [ ] 포맷 검사·관련 테스트·기존 CI를 확인한다.
- [ ] 개발 대화 기록 없는 독립 리뷰 후 단일 목적의 PR을 생성한다.

## 검토 초점

- 원본과 복제본이 서로 다른 식별자로 저장되는가.
- 이름 변경과 내용 교체가 디스플레이·공간 연결 정보를 유지하는가.
- 파일과 목록이 새 관리자에서도 일치하는가.
- 잘못된 입력이 기존 데이터나 활성 프로필을 변경하지 않는가.
- 테스트가 실제 사용자 저장 경로와 앱 상태에 접근하지 않는가.

## 범위와 제한

실제 앱 상태 캡처·프로필 적용·메뉴 막대 조작은 다음 단계로 남긴다. 이번 변경에는 제품 코드·CI·측정 범위 변경이 없다. 테스트만 추가하므로 화면 기능 구현 및 버그 수정에 해당하는 수동 조작 검증은 적용하지 않는다.

검증 실행 전 기록: 새 테스트는 `NeatProfilePersistenceTests.<UUID>` 임시 폴더만 생성하며 preferences·앱·권한·로그인 항목을 만들지 않는다. 앱 호스트 테스트는 GitHub Actions에서 실행해 로컬 사용자 상태와 격리한다.

진행 기록: 로컬 정책 테스트 5건·서명 회귀 검사 3건 및 신규 파일 SwiftFormat 검사 통과. 독립 리뷰의 fixture 기본값 문제를 보강했고 재리뷰에서 추가 조치할 문제가 없음을 확인했다. 앱 테스트·전체 정적 검사는 PR CI에서 확인한다.
