# 배치 계획 단위·통합 테스트 보강

2026-10-23, Swift 6.4 / macOS 27 환경에서 측정했다. 제품 소스·의존성·CI 설정은 변경하지 않았다.

## 검증 범위

- `NotchOverflowTests`: 0·음수·NaN·무한대 너비, 정확히 들어가는 너비와 초과 너비, 신규 항목 우선 숨김, 흩어진 그룹의 원자성, 초대형 그룹의 연쇄 숨김 방지, 오른쪽 연속 구간 보존, 너비 누락 진단을 확인한다.
- 순수 로직 통합: `MenuBarItemGroupPolicy.GroupSet`을 배치 계획에 전달하고, 결과를 섹션으로 분할한 뒤 다시 평탄화해 전체 순서 보존을 확인한다. 같은 너비로 재계산했을 때 추가 숨김이 없는지도 확인한다. 앱 실행·실제 메뉴 막대 조작·영속 저장 연동 테스트는 아니다.
- `SavedSectionOrderTests`: 종료된 앱의 이웃 위치, 현재 순서 우선, 이웃 부재, 빈 섹션, 중복 저장 항목, 다른 섹션으로 이동한 항목, 오래된 인스턴스와 제목, 네임스페이스의 정확한 일치 여부를 확인한다.
- 저장 차단 플래그 4개의 조합 16개를 모두 확인한다.

신규 테스트 정의 10개가 매개변수와 단일 시나리오를 합쳐 38개 입력 사례를 실행한다. 기존 8개를 포함한 패키지 전체 결과는 `18 tests in 3 suites passed`다. 테스트 개수와 입력 사례 개수를 구분한다.

## 같은 범위의 줄 커버리지

| 대상 | 개선 전 | 개선 후 |
|---|---:|---:|
| ThawLayout 자체 Sources | 81 / 522 (15.52%) | 379 / 522 (72.61%) |
| LayoutSolver.swift | 76 / 512 (14.84%) | 374 / 512 (73.05%) |

같은 작업 디렉터리·도구·명령으로 변경 전과 후의 LLVM JSON을 비교했다. 의존 패키지와 테스트 파일은 집계에서 제외했다. 앱의 Sonar 배지나 프로젝트 전체 커버리지 수치가 아니다. 줄 실행률은 모든 분기와 계약의 검증을 뜻하지 않는다.

```sh
swift test --package-path upstream/ThawLayout \
  --scratch-path /tmp/neat-layout-tests.<작업별임시경로>/build \
  --disable-xctest --enable-code-coverage
```

## 회귀 탐지 확인

제품 소스는 임시 패키지에 복사하고, 다음 변이를 한 번에 하나씩 적용했다. 각 실행 후 원본으로 복구했다. 컴파일 실패가 아닌 `Expectation failed`와 테스트 실패를 확인했다.

| 의도적으로 만든 회귀 | 결과 |
|---|---|
| 너비 비교 `<=`를 `<`로 변경 | 정확한 경계 너비 테스트 실패 |
| 신규 항목 집합을 비워 우선순위 제거 | 초과 배치 테스트 실패 |
| 오래된 제목의 네임스페이스 필터 비활성화 | 저장 순서 테스트 실패 |
| 프로필 적용 중 저장 차단 조건 제거 | 플래그 조합 테스트 실패 |

이 4개 표본의 탐지만 확인했으며 전체 변이 점수로 해석하지 않는다. 제품 동작을 수정하거나 버그 재현을 정상 동작으로 고정하지 않았다.

## 독립 리뷰와 정리

개발 대화 기록을 전달하지 않은 별도 리뷰 에이전트가 제품 구현·호출부·신규 테스트를 검토했다. 조치가 필요한 문제는 없었고, 별도 scratch 경로에서도 전체 18개 테스트가 통과했다. 리뷰용 임시 경로는 제거 후 부재를 확인했다.

신규 파일 두 개에 프로젝트 설정으로 SwiftFormat을 적용했고, 지정 버전 SwiftLint 0.65.1의 `sh upstream/scripts/lint.sh --strict` 결과 660개 파일에서 위반 0건이었다. 포맷 후 전체 패키지 테스트도 다시 통과했다.

단위 테스트·변이 검증용 경로 `/tmp/neat-layout-tests.wjwjrp`에는 빌드, 복사 패키지, 일회성 스크립트와 도구를 모았다. 검증 후 이 경로를 제거하고 부재를 확인했다. 테스트는 순수 값만 사용하며 앱 설치·실행, 권한·로그인 항목 등록, preferences·프로필·메뉴 막대 상태 변경은 하지 않았다. 검증 근거는 이 문서에 남겼다.

실제 화면 조작은 요청 범위에서 제외했다. 전체 앱의 로컬 빌드·테스트는 수행하지 않았으며 원격 CI 결과는 PR에서 별도로 확인한다. 남은 주요 패키지 범위는 `planLeftmostMove`와 `NewItemsPlacement` 직렬화다.
