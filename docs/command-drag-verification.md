# 히든바 Cmd 드래그 검증

검증 환경: macOS 27.0.1, Xcode 27, `feature/hidden-bar-command-drag` 브랜치.

## 구현 범위

- 메뉴바 아래 별도 히든바에서 Cmd 드래그하여 Neat 오른쪽 메뉴바에 아이콘을 꺼낸다.
- 실제 메뉴바의 아이콘을 Neat 왼쪽에 놓으면 드래그한 항목을 숨김으로 전환한다.
- 드래그 중 숨김 아이콘을 실제 메뉴바에 펼치지 않는다.
- 히든바에서 아이콘을 꺼낸 뒤에도 패널을 유지한다.
- 기존 레이아웃 저장·권한 검사와 그룹의 원자적 이동을 재사용한다.

## 자동 검사

- `./test.command`: 정책 테스트 5건, 서명 회귀 검사 3건 통과.
- `./build.command`: Release 빌드와 고정 인증서 서명·검증 통과. 결과물은 `build/Neat.app`.
- `sh scripts/lint.sh --strict`: 658개 파일, 위반 0건. 기존 길이 위반 기준 정보 277건 중 수정된 두 파일의 4건만 갱신했으며, 새 예외는 추가하지 않았다.
- 새 드롭 판정 및 기존 순서 저장·섹션 판정·바깥 클릭 테스트: 48개 테스트 통과, 매개변수별 실행 60건, 실패·건너뜀 0건. 로그는 `build/command-drag-tests.log`, 결과 번들은 `build/DerivedData/Logs/Test/Test-Thaw-2026.10.19_14-55-28-+0900.xcresult`.
- 자동 검사는 드롭 위치 판정과 Cmd 클릭 처리를 확인하며, 실제 AppKit 드래그 세션·macOS 배치 적용·재실행 유지는 확인하지 못한다. 전체 앱 테스트와 Sonar의 새 코드 80% 커버리지 검사는 실행하지 않았다.
- `swiftformat`은 설치되어 있지 않아 실행하지 못했다.

## 독립 리뷰

개발 대화 기록 없는 별도 에이전트가 요구사항과 바깥 저장소의 Git diff를 읽기 전용으로 검토했다. 그룹을 꺼낼 때 드롭 위치가 저장되지 않는 문제 1건을 발견했다. 원자적 할당 후 순서도 기록하도록 수정했으며 재검토에서 추가 조치가 필요한 문제는 발견되지 않았다.

## 실제 조작 검증

미완료. 컴퓨터 조작 도구에서 Neat의 메뉴바 아이콘이 노출되지 않고 앱 스크린샷은 숨겨진 1픽셀 창만 반환했다. SystemUIServer와 Control Center 접근도 시간 초과됐다. 다른 macOS 화면 캡처·입력 자동화 사용에 대한 사용자 응답을 기다리고 있다. 사용자 배치는 변경하지 않았다.

남은 검증은 히든바에서 아이콘 두 개 연속 꺼내기, 메뉴바에서 Neat 왼쪽으로 이동, 드래그 중 펼침 방지, Escape·잘못된 드롭 취소, 대기 후 및 앱 재실행 후 배치 유지이다. 실제 조작 검증 전까지 해결 완료로 간주하지 않는다.

바깥 저장소에는 원격이 없어 PR·원격 CI·승인은 수행하지 않았다. 로컬 테스트와 독립 리뷰를 원격 승인으로 간주하지 않는다.
